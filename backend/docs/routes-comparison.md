## 二、每条路线深度分析

### 路线 A: DEX-DEX 套利（已验证不可行）

- 164,814 个数学上的机会，0 个链上真实存在
- 10 笔真实交易 100% revert
- **根因：2-3 秒延迟 vs <0.1 秒机会窗口**
- 即使优化到极致，公共 RPC 无法突破 200ms 的 Timeboost 壁垒
- **评分：D（不可行，除非获得 Express Lane 或自建节点）**

### 路线 B: 闪电贷放大

- Aave V3 on Arbitrum 支持 20 种资产
- WETH 流动性 0.1 ETH（低，但 USDC 有 1048）
- 闪电贷手续费 0.05%（Aave V3）
- **关键问题：放大了金额但不解决速度，同样 100% revert**
- **评分：C（与路线 C 结合时有价值）**

### 路线 C: 清算机器人（最有潜力）

- Aave V3 合约完全可用（Pool + DataProvider）
- 当前 1 个高风险头寸（HF=1.0449，离清算只差 4.5%）
- 清算奖励 5-10%（协议硬编码，确定性高）
- **机会窗口：秒到分钟级（我们的 2-3 秒延迟可以接受）**
- 可以用闪电贷执行（零本金）
- **评分：A（最有可能盈利的方向）**

### 路线 E: 跨链套利

- Arbitrum/Base/Optimism 价差 <0.08%
- 扣除桥接费（$0.5-2）后无利润空间
- 实现复杂度高（多链部署 + 桥接集成）
- **评分：D（主流对不可行，极端冷门对可能有机会但风险太大）**

## 三、最优组合方案

### 推荐策略：清算机器人 + 闪电贷（C + B）

```
触发条件: Aave 借款人 healthFactor < 1.0
执行流程:
  1. 用闪电贷借入债务代币（如 USDC）
  2. 调用 Aave liquidationCall 清算不健康头寸
  3. 获得抵押品（如 WETH）+ 5-10% 清算奖励
  4. 在 DEX 上卖出抵押品换回 USDC
  5. 还闪电贷 + 手续费
  6. 剩余 = 净利润
```

**为什么这个方案可行：**

1. **时间窗口足够** — 清算机会在 healthFactor 缓慢下降过程中产生，存活秒到分钟
2. **利润确定** — 5-10% 清算奖励是协议规定的，不像套利需要实时价差
3. **零本金** — 闪电贷提供资金，只需 Gas 费
4. **竞争较少** — 清算者比套利者少得多（尤其在 Arbitrum L2）
5. **可复用现有代码** — Go 后端、RPC 连接、Web3 客户端都可以复用

**一笔成功清算的利润示例：**
```
债务: 1000 USDC（清算 50%）
清算奖励: 5%
获得抵押品: ~525 USDC 等值的 WETH
卖出得到: ~525 USDC
还闪电贷: 500 USDC + 0.25 USDC（0.05% 手续费）
Gas: ~$0.05
净利润: 525 - 500 - 0.25 - 0.05 = $24.70
```

### 并行保留：DEX-DEX 套利（长时间后台运行）

- 保留现有套利系统在后台运行（dry-run + eth_call 验证）
- 只在 eth_call 通过时开启执行
- 市场剧烈波动时可能偶尔捕获到机会
- 作为补充收入，不作为主要收入
