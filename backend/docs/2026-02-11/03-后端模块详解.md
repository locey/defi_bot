## 1. 命令行入口 (cmd/)

项目提供 26 个命令行入口，涵盖服务启动、测试、诊断等场景。

### 1.1 主服务

| 命令 | 路径 | 说明 |
|------|------|------|
| **server** | `cmd/server/main.go` | 主服务入口，启动完整套利系统 |

**启动流程：**
1. 加载配置 (Viper → YAML)
2. 初始化数据库 (PostgreSQL + GORM)
3. 创建 Web3 客户端 (RPC 连接池)
4. 初始化 Redis 缓存
5. 创建 CEX 采集器 (Binance)
6. 创建数据采集器 (并发模式)
7. 初始化策略引擎
8. 创建执行器
9. 启动调度器 (标准 / 高性能)
10. 启动 API 服务 (Gin)
11. 注册优雅关闭 (Graceful Shutdown)

## 2. 配置管理 (internal/config/)

### 2.1 配置结构

```go
type Config struct {
    Database    DatabaseConfig    // PostgreSQL 连接配置
    Blockchain  BlockchainConfig  // 区块链 RPC 配置
    Contracts   ContractsConfig   // 合约地址配置
    Keeper      KeeperConfig      // 签名私钥配置
    Dexes       []DexConfig       // DEX 协议配置列表
    Tokens      []TokenConfig     // 代币配置列表
    Scheduler   SchedulerConfig   // 调度器配置
    Arbitrage   ArbitrageConfig   // 套利参数配置
    Cex         CexConfig         // CEX API 配置
    CEXDEX      CEXDEXConfig      // CEX-DEX 套利配置
    Metrics     MetricsConfig     // 指标采集配置
    Telegram    TelegramConfig    // Telegram 通知配置
}
```

### 2.2 关键配置项

**BlockchainConfig：**
- `rpc_urls`: 支持多节点 RPC 连接池
- `ws_url`: WebSocket URL (实时事件)
- `chain_id`: 链 ID
- `timeout`, `retry_count`, `retry_delay`: 连接参数

**DexConfig：**
- 每个 DEX 独立配置: router, factory, quoter 地址
- V3 支持多费率层级: 500 (0.05%), 3000 (0.3%), 10000 (1%)

**SchedulerConfig：**
- `collection_interval`: 数据采集间隔
- `analysis_interval`: 策略分析间隔
- `execution_enabled`: 是否启用执行
- `high_performance_mode`: 高性能模式开关

**ArbitrageConfig：**
- `min_profit_rate`: 最小利润率阈值
- `max_slippage`: 最大滑点容忍
- `max_path_length`: 最大路径长度 (3-5 跳)

### 3.2 采集流程

```
ConcurrentCollector.Start()
├── goroutine 1-N: DEX 价格采集 (每个交易对一个)
│   └── RPC 调用 getReserves() / slot0() / liquidity()
├── goroutine N+1: CEX Ticker 采集
│   └── Binance REST API / WebSocket
├── goroutine N+2: Gas 价格采集
│   └── eth_gasPrice / eth_maxPriorityFeePerGas
├── goroutine N+3: 区块订阅
│   └── eth_subscribe("newHeads")
└── goroutine N+4: 新池监听
    └── eth_subscribe("logs") → PairCreated / PoolCreated
```

### 3.3 PoolWatcher 详解

**功能：** 实时监听 DEX Factory 合约事件，发现新创建的流动性池

**监听事件：**
- Uniswap V2 Factory: `PairCreated(token0, token1, pair, allPairsLength)`
- Uniswap V3 Factory: `PoolCreated(token0, token1, fee, tickSpacing, pool)`

**输出：** `NewPoolEvent` channel → 下游路径更新

### 4.2 核心类型

```go
// 套利机会
type ArbitrageOpportunity struct {
    Path          []PathNode      // 交换路径
    InputAmount   *big.Int        // 输入金额
    OutputAmount  *big.Int        // 输出金额
    Profit        *big.Int        // 预期利润
    ProfitRate    float64         // 利润率
    GasCost       *big.Int        // Gas 成本
    Confidence    float64         // 置信度
    Strategy      string          // 策略类型
    Timestamp     time.Time       // 检测时间
}

// 池信息
type PoolInfo struct {
    Address     common.Address    // 池地址
    Token0      common.Address    // Token0 地址
    Token1      common.Address    // Token1 地址
    Reserve0    *big.Int          // V2 储备量0
    Reserve1    *big.Int          // V2 储备量1
    Fee         uint32            // V3 费率
    SqrtPriceX96 *big.Int         // V3 价格
    Tick        int32             // V3 当前 Tick
    Liquidity   *big.Int          // V3 流动性
    Protocol    string            // 协议名称
    Version     int               // 协议版本 (2/3)
}
```

### 4.3 Fast Detector (事件驱动检测)

**设计理念：** 不做全量扫描，而是增量监听价格变化，仅重新计算受影响的路径。

**工作流程：**
1. **启动时** - 构建 Token 图谱，预计算所有可能的套利路径 (3-5 跳)
2. **运行时** - 监听价格变化事件
3. **增量计算** - 仅重新计算包含价格变化 Token 的路径
4. **过滤输出** - 利润率 > 阈值的机会进入执行队列

**路径搜索算法：**
- 构建 Token → Pool 的有向图
- DFS 搜索 3-5 跳的环形路径 (起点 = 终点)
- 支持长尾代币路径（经蜜罐检测过滤）

### 4.4 利润计算器

**V2 AMM 公式：**
```
amountOut = (amountIn * 997 * reserveOut) / (reserveIn * 1000 + amountIn * 997)
```

**V3 集中流动性计算：**
```
基于 sqrtPriceX96 和 liquidity：
- token0 → token1: Δy = L × (√P_new - √P_old)
- token1 → token0: Δx = L × (1/√P_old - 1/√P_new)
```

### 4.5 蜜罐检测器

**检测维度：**
1. 合约代码大小检查
2. ERC20 标准合规检查
3. 可疑 Selector 检测 (隐藏函数)
4. 黑名单机制
5. 缓存 + TTL (避免重复检查)

### 5.2 执行流程

```
ArbitrageExecutor.Execute(opportunity)
│
├── 1. 验证机会有效性
│   └── 检查路径、金额、过期时间
│
├── 2. 交易模拟 (Simulator)
│   └── eth_call → 验证盈利性
│   └── 返回 SimResult (profit, gasUsed)
│
├── 3. Gas 估算 (GasPricer)
│   └── 当前 Gas 价格 + 20% 缓冲
│   └── EIP-1559 → maxFeePerGas + maxPriorityFeePerGas
│
├── 4. 构建交易 (ContractCaller)
│   ├── 自有资金: executeStrategy(ArbitrageParams)
│   └── 闪电贷: executeFlashLoanArbitrageWithPlatform(...)
│
├── 5. 发送交易
│   ├── 标准模式: eth_sendTransaction
│   ├── Flashbots: Flashbots Protect RPC
│   └── 私有模式: Sequencer 私有端点
│
├── 6. 等待确认
│   └── WaitMined() → TransactionReceipt
│
├── 7. 解析结果
│   └── 解析事件日志 → 实际利润
│
└── 8. 持久化 (AsyncWriter)
    └── 异步批量写入数据库
```

### 5.3 ContractCaller 调用方式

**方式一：自有资金套利 (executeStrategy)**
```go
ArbitrageParams {
    tokenIn      address    // 输入代币
    tokenOut     address    // 输出代币
    amountIn     uint256    // 输入金额
    minProfit    uint256    // 最小利润
    swapSteps    []SwapStep // 交换步骤
    strategyType uint8      // 0=OWN_FUNDS, 1=FLASH_LOAN
}
```

**方式二：闪电贷套利 (executeFlashLoanArbitrageWithPlatform)**
```go
参数:
    asset        address    // 闪电贷资产
    amount       uint256    // 借贷金额
    platform     uint8      // 0=Aave_V2, 1=Aave_V3, 2=DYDX
    swapParams   bytes      // 编码后的交换参数
```

### 5.4 异步写入器 (AsyncWriter)

**设计：** 非阻塞写入，防止数据库操作阻塞执行热路径

```
Executor → AsyncWriter.Write(record) → Buffered Channel (100)
                                              │
                                    ┌─────────┴─────────┐
                                    │  Batch Processor   │
                                    │  50 条/批 或 5s 刷新 │
                                    └─────────┬─────────┘
                                              │
                                         PostgreSQL
```
