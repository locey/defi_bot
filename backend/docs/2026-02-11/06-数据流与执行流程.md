## 2. 数据采集流程

### 2.1 DEX 价格采集

```
ConcurrentCollector.collectDexPrices()
│
├── 遍历所有已配置交易对
│   │
│   └── goroutine (每对一个)
│       │
│       ├── V2 交易对
│       │   ├── getReserves() → (reserve0, reserve1)
│       │   ├── 计算价格: price = reserve1 / reserve0
│       │   └── 写入数据库 + Redis 缓存
│       │
│       └── V3 交易对
│           ├── slot0() → (sqrtPriceX96, tick, ...)
│           ├── liquidity() → currentLiquidity
│           ├── 计算价格: price = (sqrtPriceX96 / 2^96)^2
│           └── 写入数据库 + Redis 缓存
│
└── 等待所有 goroutine 完成
    └── 统计：成功数、失败数、耗时
```

### 2.2 CEX 价格采集

```
CexCollector.collect()
│
├── 模式 1: REST API 轮询
│   ├── GET /api/v3/ticker/24hr?symbol=ETHUSDT
│   ├── 解析: lastPrice, bidPrice, askPrice, volume
│   └── 写入数据库 + Redis 缓存
│
└── 模式 2: WebSocket 实时推送
    ├── 连接: wss://stream.binance.com:9443/ws
    ├── 订阅: ethusdt@ticker, btcusdt@ticker, ...
    ├── 接收: 实时 Ticker 数据
    └── 更新 Redis 缓存 (低延迟)
```

### 2.3 新池发现流程

```
PoolWatcher.Watch()
│
├── 订阅 V2 Factory 事件
│   └── event PairCreated(token0, token1, pair, allPairsLength)
│       ├── 验证 Token 合法性
│       ├── 蜜罐检测
│       ├── 创建 NewPoolEvent
│       └── 发送到 Channel → 路径更新
│
└── 订阅 V3 Factory 事件
    └── event PoolCreated(token0, token1, fee, tickSpacing, pool)
        ├── 验证 Token 合法性
        ├── 蜜罐检测
        ├── 创建 NewPoolEvent
        └── 发送到 Channel → 路径更新
```

## 3. 策略分析流程

### 3.1 标准模式 (定时触发)

```
Scheduler.analyzeOpportunities() [每 N 秒触发]
│
├── 从缓存/数据库加载最新价格
│
├── Strategy.FindOpportunities()
│   │
│   ├── PathFinder.FindPaths()
│   │   ├── 构建 Token 有向图
│   │   ├── DFS 搜索环形路径 (深度 3-5)
│   │   └── 返回候选路径列表
│   │
│   ├── ProfitCalculator.CalculatePathOutput(path)
│   │   ├── 按步骤计算每一跳输出
│   │   │   ├── V2: amountOut = (in * 997 * rOut) / (rIn * 1000 + in * 997)
│   │   │   └── V3: 基于 sqrtPriceX96 和 liquidity 计算
│   │   ├── 最终输出 vs 初始输入 → 利润
│   │   └── 扣除 Gas 成本 → 净利润
│   │
│   ├── HoneypotDetector.IsSafe(token)
│   │   ├── 检查缓存
│   │   ├── 合约代码分析
│   │   └── 返回安全/不安全
│   │
│   ├── OpportunityValidator.Validate(opp)
│   │   ├── 利润率 > 最小阈值？
│   │   ├── Gas 成本合理？
│   │   └── 流动性充足？
│   │
│   └── Optimizer.Optimize(opp)
│       ├── 优化输入金额
│       ├── 计算最优滑点
│       └── 评估置信度
│
└── 返回 []ArbitrageOpportunity (排序: 利润率降序)
```

### 3.2 高性能模式 (事件驱动)

```
ArbitrageDetector (Fast Detector)
│
├── 启动时: 预计算
│   ├── 加载所有交易对和池
│   ├── 构建 Token → Pool 图谱
│   ├── DFS 预计算所有 3-5 跳路径
│   └── 存储路径 → 受影响的 Token 映射
│
├── 运行时: 增量检测
│   │
│   ├── 监听价格变化事件
│   │   └── PriceUpdate{token, pool, newPrice}
│   │
│   ├── 查找受影响的路径
│   │   └── 仅包含该 Token 的路径 (非全量扫描)
│   │
│   ├── 重新计算受影响路径的利润
│   │   └── ProfitCalculator.CalculatePathOutput()
│   │
│   ├── 过滤: 利润率 > 阈值
│   │
│   └── 输出: opportunity → 执行队列
│
└── 优势: O(受影响路径数) vs O(全部路径数)
```

### 3.3 CEX-DEX 套利检测

```
CexDexDetector.Detect()
│
├── 获取 CEX 价格 (Redis/WebSocket)
│   └── Binance: ETHUSDT, BTCUSDT, ...
│
├── 获取 DEX 价格 (Redis/链上)
│   └── Uniswap/SushiSwap: WETH/USDC, WBTC/USDC, ...
│
├── 计算价差
│   ├── spread = |cexPrice - dexPrice| / min(cexPrice, dexPrice)
│   └── direction = cexPrice > dexPrice ? "buy_dex_sell_cex" : "buy_cex_sell_dex"
│
├── 扣除成本
│   ├── DEX 交易 Gas
│   ├── CEX 手续费 (0.1%)
│   ├── DEX 滑点
│   └── 提币/充币费用
│
└── 净利润 > 阈值 → 发出机会
```

## 4. 交易执行流程

### 4.1 完整执行流程

```
ArbitrageExecutor.Execute(opportunity)
│
├── Step 1: 验证有效性
│   ├── 路径是否为环形 (起点 = 终点)
│   ├── 金额 > 0
│   ├── 机会是否过期 (< 30s)
│   └── 利润率是否仍满足阈值
│
├── Step 2: 交易模拟
│   ├── Simulator.Simulate(params)
│   │   ├── 构建 callData
│   │   ├── eth_call (本地模拟)
│   │   └── 解析返回值: 预期输出金额
│   │
│   ├── SimResult
│   │   ├── expectedProfit: 预期利润
│   │   ├── gasUsed: Gas 消耗
│   │   ├── isProfitable: 是否盈利
│   │   └── confidence: 置信度
│   │
│   └── 不盈利 → 放弃执行 (记录原因)
│
├── Step 3: Gas 估算
│   ├── GasPricer.GetPrice()
│   │   ├── eth_gasPrice
│   │   ├── eth_maxPriorityFeePerGas
│   │   └── baseFee (从区块头)
│   │
│   ├── EIP-1559 模式
│   │   ├── maxFeePerGas = baseFee * 2 + maxPriorityFee
│   │   └── maxPriorityFeePerGas = 建议值
│   │
│   └── Gas Limit = estimateGas() * 1.2 (20% 缓冲)
│
├── Step 4: 构建交易
│   ├── ContractCaller.BuildTx(params)
│   │
│   ├── 自有资金模式
│   │   ├── ABI 编码 ArbitrageParams
│   │   └── 调用 ArbitrageCore.executeStrategy()
│   │
│   └── 闪电贷模式
│       ├── 编码 swapParams
│       └── 调用 ArbitrageCore.executeFlashLoanArbitrageWithPlatform()
│
├── Step 5: Nonce 管理
│   └── NonceTracker.GetNextNonce()
│       ├── 本地缓存 nonce
│       ├── 与链上 nonce 对比
│       └── 取最大值 + 1
│
├── Step 6: 签名 & 发送
│   ├── 标准模式
│   │   └── eth_sendRawTransaction
│   │
│   ├── Flashbots 模式 (Ethereum)
│   │   └── Flashbots Protect RPC
│   │
│   └── 私有模式 (Arbitrum)
│       └── Sequencer 私有端点
│
├── Step 7: 等待确认
│   ├── WaitMined() → TransactionReceipt
│   ├── 超时处理 (60s)
│   └── receipt.Status == 1 → 成功
│
├── Step 8: 解析结果
│   ├── 解析事件日志
│   │   ├── VaultArbitrageExecuted → 利润金额
│   │   └── FlashLoanExecuted → 利润金额
│   │
│   └── ExecutionResult
│       ├── txHash: 交易哈希
│       ├── gasUsed: 实际 Gas 消耗
│       ├── gasCost: Gas 费用 (ETH)
│       ├── profit: 实际利润
│       └── success: 是否成功
│
└── Step 9: 持久化
    └── AsyncWriter.Write(record)
        └── buffered channel → 批量写入 PostgreSQL
```

## 5. 调度器流程

### 5.1 标准调度器

```
Scheduler.Start()
│
├── cron Job 1: 数据采集 (每 10s)
│   └── ConcurrentCollector.Collect()
│       ├── DEX 价格采集
│       ├── CEX 价格采集
│       └── Gas 价格采集
│
├── cron Job 2: 策略分析 (每 15s)
│   └── Strategy.FindOpportunities()
│       ├── 路径搜索
│       ├── 利润计算
│       └── 机会过滤
│
├── cron Job 3: 交易执行 (触发式)
│   └── Executor.Execute(bestOpportunity)
│       ├── 模拟 → 验证 → 执行
│       └── 记录结果
│
└── cron Job 4: 清理任务 (每 1h)
    └── 清理过期缓存、日志归档
```

### 5.2 高性能调度器

```
HighPerformanceScheduler.Start()
│
├── 事件循环 (Event Loop)
│   │
│   ├── select {
│   │   case block := <-blockCh:        // 新区块
│   │   │   └── 触发全量价格刷新
│   │   │
│   │   case pool := <-newPoolCh:       // 新池
│   │   │   └── 更新路径图谱
│   │   │
│   │   case price := <-priceUpdateCh:  // 价格更新
│   │   │   └── 增量策略分析
│   │   │
│   │   case opp := <-opportunityCh:    // 新机会
│   │   │   └── 立即执行
│   │   │
│   │   case <-ticker.C:                // 心跳
│   │       └── 健康检查 + 指标上报
│   │   }
│
└── 优势: 事件驱动，最小延迟
```

## 7. 缓存策略

### 7.1 Redis 缓存层级

```
Redis
├── price:{chain}:{pair}:{dex}     → 最新价格 (TTL: 30s)
├── gas:{chain}                     → Gas 价格 (TTL: 15s)
├── reserves:{pair}                 → V2 储备量 (TTL: 30s)
├── v3pool:{pool}                   → V3 池状态 (TTL: 30s)
├── ticker:{exchange}:{symbol}      → CEX Ticker (TTL: 10s)
├── depth:{exchange}:{symbol}       → 订单簿 (TTL: 10s)
└── honeypot:{token}                → 蜜罐检测结果 (TTL: 1h)
```

### 7.2 缓存读写策略

```
读取: Cache First → 命中返回 → 未命中查链上/API → 写回缓存
写入: Write Through → 同时更新缓存和数据库
失效: TTL 自动过期 + 价格变化主动失效
```
