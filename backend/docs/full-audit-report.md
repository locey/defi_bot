## 二、残酷的真相：行业竞争现状（2025 年实证数据）

### Arbitrum MEV 竞争格局

基于最新研究数据（2025 年 4-7 月 Timeboost 拍卖分析，15.1 万次拍卖）：

| 指标 | 数据 |
|------|------|
| 顶部 2 个实体占 Timeboost 拍卖胜率 | **>90%** |
| Express Lane 交易 revert 率 | **22%** |
| 独立搜索者保留利润比例 | **<10%**（90%+ 交给区块构建者） |
| CEX-DEX 套利前 3 大搜索者占市场份额 | **~75%** |
| 套利机会衰减时间 | **0.5-2 秒** |

### Timeboost 对你的影响

Arbitrum 已上线 Timeboost 机制：
- 没有购买 Express Lane 的交易有 **200ms 延迟**
- Express Lane 拍卖被 2 个实体垄断
- 这意味着：你的交易永远比顶级搜索者晚 200ms 到达 Sequencer

### 你 vs 专业搜索者

| 维度 | 专业 MEV 搜索者 | 你的项目 |

| Timeboost Express Lane | 90%+ 胜率 | 不参与 |
| 利润保留率 | 个位数百分比 | N/A |

### 对主流代币对套利的结论

**在 WETH/USDC、WETH/WBTC 等主流对上做 DEX-DEX 套利，你没有任何竞争力。这不是代码质量问题，而是市场结构问题。**

## 五、精确行动计划

### 阶段 A：让系统跑起来（1-2 天）

```
步骤 1: 编译合约
  cd contract && npx hardhat compile

步骤 2: 本地环境
  cd backend && make dev-init  # 启动 PostgreSQL + Redis + 迁移 + 种子数据

步骤 3: 创建 Keeper 钱包
  - 用 MetaMask 创建新钱包（专用于机器人，不要用个人钱包）
  - 导出私钥，填入 configs/config.yaml 的 keeper.private_key
  - 向该地址转入少量 ETH（Arbitrum 上 ~0.001 ETH 用于 Gas 测试）

步骤 4: 测试网先跑
  make run CONFIG_FILE=configs/config.test.yaml
  观察日志，确认：
  - 数据采集正常（Sync 事件、Multicall 储备量）
  - 策略引擎发现机会（即使 dry-run 模式）
  - 没有 panic 或致命错误

步骤 5: 切到 Arbitrum 主网 dry-run
  配置 scheduler.dry_run: true
  make run CONFIG_FILE=configs/config.yaml
  跑 24-48 小时，收集数据：
  - 发现了多少机会？
  - 预期利润多少？
  - Gas 估算合理吗？
```

### 阶段 B：验证能否赚钱（1-2 周）

```
步骤 6: 分析 dry-run 数据
  - 如果 0 个机会 → 问题在数据采集或路径发现
  - 如果有机会但预期利润 < Gas → 策略需要调整
  - 如果有机会且利润 > Gas → 可以尝试小额实盘

步骤 7: 小额实盘测试
  - 向 Keeper 钱包充 $5-10 的 ETH + $50 的 USDC
  - 关闭 dry_run，开启 enable_execution
  - 限制：只走自有资金模式（不用闪电贷）
  - 运行 24 小时，观察实际执行结果

步骤 8: 如果亏损
  - 分析 Arbiscan 上的交易：是被抢跑了？还是滑点过大？还是 Gas 估算不准？
  - 调整参数，再试
```

### 阶段 C：面试准备（持续进行）

```
步骤 9: 内化面试文档
  - 读 backend/docs/interview-prep.md
  - 对每个场景，打开对应的源码文件，理解每一行改动
  - 重点理解：闪电贷修复、V3 数学、事件驱动架构

步骤 10: 收集真实数据
  - dry-run 期间记录的数据就是你的面试素材
  - "日均扫描 X 个池子，发现 Y 个套利机会，平均利润率 Z%"
  - 即使不赚钱，"我分析了为什么不赚钱"也是很好的面试答案

步骤 11: 准备 Arbiscan 分析案例
  - 去 arbiscan.io 搜索成功的套利交易
  - 分析他们的路径、Gas、利润
  - 面试时说："我研究了链上 100+ 笔套利交易..."
```

## 六、关于收益预期的诚实建议

### $100/天 的可行性分析

| 条件 | 当前状态 | 需要 |
|------|---------|------|
| 基础设施 | 公共 RPC + 本地 | 至少付费 RPC（$49/月） |
| 资金 | ~$140 | 闪电贷不需本金，自有资金至少 $500+ |
| 策略 | 长尾代币 + 新池子 | 需要实盘验证 |
| 延迟 | 200ms+（Timeboost 限制） | 短期无法改善 |
| 蜜罐过滤 | 已实现 | 需要实盘校准准确率 |

**我的判断：**
- $100/天在起步阶段（3-6 个月内）**不现实**
- $10-30/天在长尾策略上**有可能**（如果蜜罐检测准确且发现足够的小机会）
- $0-5/天是最现实的初期预期
- 这个项目的**最大回报在面试价值**，不在直接收益

### $10K-50K/天 的可行性

**需要完全不同的路径：**
- 转向做市商（Market Making）而非套利
- 或做跨链桥接套利（需要多链部署 + 大量资金）
- 或获得机构级基础设施投入
- 作为个人项目，这个量级在可预见的将来不现实
