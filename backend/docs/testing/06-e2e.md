# 06 - 端到端测试 (E2E)

## 模块概述

端到端测试验证完整的套利流程：**数据采集 → 策略分析 → (可选) 交易执行**。

## 关键文件

| 文件 | 说明 |
|------|------|
| `cmd/e2e/main.go` | E2E 测试入口 |

## 测试命令

```bash
# 基础 E2E (跳过交易对发现和深度采集，使用已有数据)
go run cmd/e2e/main.go -config configs/config.yaml -skip-pairs -skip-depth

# 完整 E2E (包含交易对发现，耗时较长)
go run cmd/e2e/main.go -config configs/config.yaml -skip-depth

# Dry-run 模式 (默认，不发送交易)
go run cmd/e2e/main.go -config configs/config.yaml -skip-pairs -skip-depth

# 实际执行模式 (需要 keeper 私钥和合约权限)
go run cmd/e2e/main.go -config configs/config.yaml -skip-pairs -skip-depth -execute
```

### 命令行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-config` | `configs/config.test.yaml` | 配置文件路径 |
| `-migrate` | false | 执行数据库迁移 |
| `-seed` | false | 初始化种子数据 |
| `-cleanup` | false | 清理其他链的残留数据 |
| `-execute` | false | 是否实际发送交易 |
| `-skip-pairs` | false | 跳过交易对发现 |
| `-skip-depth` | false | 跳过 V3 深度采集 |
| `-min-profit-rate` | -1 | 覆盖最小利润率 (%, -1 使用配置值) |
| `-gas-multiplier` | 2.0 | Gas 成本乘数 |

## 测试流程

### 阶段 1: 环境初始化
1. 加载配置 (`config.yaml`)
2. 初始化 PostgreSQL 数据库连接
3. 可选: 执行迁移 + 种子数据
4. 初始化 Web3 客户端
5. 可选: 初始化 Redis 缓存
6. 可选: 初始化 CEX (Binance) 采集器

### 阶段 2: 数据采集
1. 创建数据采集器 (Collector)
2. 如果 `skip-pairs=false`: 执行交易对发现
3. 采集价格数据 (CollectPriceOnly)
4. 如果 `skip-depth=false`: 采集 V3 深度数据

### 阶段 3: 策略分析
1. 创建策略引擎 (StrategyEngine)
2. 启动策略引擎 (加载历史数据)
3. 调用 FindOpportunities 查找套利机会
4. 输出最佳机会详情 (profit_rate, expect_profit, path, amount_in)

### 阶段 4: 交易执行 (仅 `-execute` 模式)
1. 构建 ArbitrageParams
2. 生成 CallData
3. 发送交易
4. 等待确认
5. 解析事件日志

## 预期结果

### 正常情况
- **无套利机会**: 最常见的结果。市场效率高，价差不足以覆盖 Gas 成本
- **有套利机会但不执行**: dry-run 模式下，输出 CallData 后退出

### 异常处理
- **"reserves are too small"**: 部分交易对流动性不足，正常跳过
- **"429 Too Many Requests"**: RPC 速率限制，部分请求失败，不影响整体流程
- **"不支持的协议: binance_spot"**: CEX 交易对不走 DEX 采集，正常跳过

## 验证标准

| 检查项 | 通过条件 |
|--------|----------|
| 初始化 | 所有组件正常初始化 |
| 数据采集 | 至少部分交易对价格采集成功 |
| 策略分析 | FindOpportunities 正常返回 |
| 退出码 | exit code = 0 |
