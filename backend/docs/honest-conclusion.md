**六次测试，零盈利。**

## 根因确认

不是代码问题——代码完全正确（10 笔交易成功到达 DEX swap 层）。

不是策略问题——172 个高置信度机会的利润率在 0.5-4% 的合理范围。

是**速度问题**——用公共 RPC（最快 110ms/次）采集 + 计算 + 模拟 + 提交的总延迟 ~500ms-2500ms，而套利机会在 Arbitrum 上存活 <100ms。

## 数学证明

```
你的 eth_call 延迟: ~76ms
但你发现机会的延迟: ~3000ms（采集周期 3 秒）
总延迟: ~3076ms

套利机会存活时间: <100ms（Timeboost Express Lane 搜索者在 <10ms 内吃掉）

即使你把 eth_call 优化到 0ms，发现机会的 3000ms 延迟仍然是致命的。
即使把采集周期降到 100ms，Alchemy 免费版请求量也不够。
```

## 要让 DEX-DEX 套利可行，需要

1. **自建 Arbitrum 全节点**（$200-500/月）→ 采集延迟从 3000ms 降到 <50ms
2. **购买 Timeboost Express Lane**（$50-500/天）→ 消除 200ms 强制延迟
3. **Co-location**（$500-2000/月）→ 网络延迟从 100ms 降到 <1ms

**最低成本：$200/月（自建节点），可能提升到 1-5% 的成功率**
**有竞争力的成本：$3000+/月**
